# 图片创作工作台设计

## 目标

把当前依赖 Infinite Canvas 的「图片创作」页，改成 Hapi 自研的图片创作工作台。页面参考 `mid.mjdraw.cn/home/#/ai/gpt-image` 的使用方式，但只保留最核心的生成链路：提示词、参考图、参数、结果、历史。

这个页面要服务真实的 Hapi 站内 Key 体系。用户在页面里选择自己的 Key 后，直接发起图片生成或改图任务，生成结果、失败原因、使用记录都能回到 Hapi 体系里追踪。

现有 `/image-creation` 路由和左侧「图片创作」菜单名保留，只替换内部实现。

## 范围

- 支持提示词输入。
- 支持上传参考图。
- 支持选择站内 active API Key。
- 支持选择模型、比例、张数和基础生成参数。
- 支持生成结果预览、下载、再次生成、设为参考图。
- 支持最近任务/历史记录。
- Web 端和桌面端共用同一套页面。

## 不做的事

- 不做无限画布。
- 不做图层编辑器。
- 不做自由绘制、圈选、涂抹式画布。
- 不做模板排版工具。
- 不依赖外部 Infinite Canvas 页面。

## 页面结构

页面按「输入区、预览区、参数区」三块组织。

- 输入区：提示词、参考图上传、历史入口。
- 预览区：任务状态、生成中的占位、结果图卡片。
- 参数区：Key、模型、比例、张数、风格/强度类参数。

桌面端优先三栏布局，窄屏时自动折叠为上下堆叠。

## 数据流

1. 用户从站内 Key 列表中选一个可用 Key。
2. 用户输入提示词并上传参考图。
3. 前端做基础校验后提交生成任务。
4. 后端根据 Key 归属与权限调用图片生成能力。
5. 前端轮询或接收任务状态，展示进度、结果和错误。
6. 任务完成后写入历史，供再次生成和下载使用。

## 接口原则

- 前端只传 `key_id`，不把原始密钥发给第三方页面。
- 参考图按文件上传处理，不先做画布裁切层。
- 图片生成要保留任务 ID，方便刷新后恢复状态。
- 结果列表要能区分成功、失败、进行中。

## 交互原则

- 首次进入页面时默认选中一个可用 Key。
- 没有可用 Key 时，提示先去「API 密钥」页配置。
- 参考图最多允许 4 张，避免把页面做成素材仓库。
- 提交后按钮进入 loading，避免重复下发。
- 失败时保留原始提示词和参考图，方便重试。

## 验证

- 前端测试覆盖参数校验、Key 选择、任务提交和结果渲染。
- 如果后端新增图片任务接口，再补对应的服务测试和回归用例。
- 最终页面需要通过本地构建验证，并在真实站内 Key 下做一次端到端生成检查。
